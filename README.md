# ThunderPanSync

把本地文件夹**单向**上传到**迅雷云盘**的 Windows 桌面应用（只能上传，不能下载或恢复）。

原生 WinForms 界面（不是浏览器套壳），主程序 107 KB（109,568 B）。

> ⚠️ **下载前必须知道的 4 件事**（不接受就别装，装了没人能替你兜底）
>
> **1. 可能违反迅雷的协议。** 它靠自动化驱动迅雷网页版上传，不是官方接口。这可能违反《迅雷网盘服务协议》第 3.12 条（未授权衍生软件）和第 3.4.3 条（未经书面同意借助迅雷软件发展衍生产品/服务），迅雷可**不事先通知**单方面终止你的账号。
>
> **2. 封号 = 云盘里所有文件一起没。** 账号被终止后，迅雷有权**永久删除你云盘里的全部文件** —— 不只是这个工具传的，也包含你以前手动传的，且没有义务返还数据（协议 2.8 条）。
>
> **3. 只能上传，不能下载或恢复。** 它不是备份软件：没有恢复功能、不保留版本历史、不与云端对账（云端文件被删它不会发现也不会重传）。请把本地原文件当作唯一可靠副本。
>
> **4. 本机会开一个没有认证的调试端口**（仅 `127.0.0.1`，局域网/公网连不上，但本机任何程序都能连上去接管这个已登录的会话，且应用运行期间一直开放）。安装包未签名，SmartScreen 会警告。
>
> 最省事的自保办法：注册一个专门的迅雷小号给这个工具用 —— 万一被封，没的是这个小号，不是你攒了几年的那个号。

**这不是"同步盘"，也不是"备份软件"。** 真正的备份要能恢复、能校验云端是否还在 —— 它三样都不做（详见下面「它不做什么」与「已知边界」）。

如果你要的是"给重要文件多一份保险"，用 OneDrive / 阿里云盘 / rclone 这类有官方接口的方案更安全。这个工具只在一个场景下有优势：**你本来就在用迅雷云盘，只想把文件夹里的新文件自动丢进去，并且清楚上面 4 条。**

版本说明、系统要求、卸载与"不适合谁用"见 **[RELEASE-NOTES.md](RELEASE-NOTES.md)**。

## 它做什么

监视你指定的文件夹，文件发生变化后自动上传到迅雷云盘的指定目录。

| 能力 | 状态 |
|---|---|
| 监视多个文件夹，自动上传 | ✅ |
| 定时轮询（默认 60 秒） | ✅ |
| 幂等：未修改的文件不重复上传 | ✅ |
| 开机自启 | ✅ |
| 关闭窗口最小化到托盘，备份继续 | ✅ |
| 空文件跳过（云盘不接受 0 字节） | ✅ |
| 上传后去云端列表核实**该文件**是否真的入库（核实不了会显示「待核实」，不会当成功） | ✅ |
| 实时进度条（第 x/y 个 · 文件名 · 本轮已传字节 / 本轮总字节） | ✅ |
| 失败自动退避 + 连续失败熔断 | ✅ |
| 日志按天分文件 | ✅ |
| 风险告知会随告知版本更新重新弹出（不是只弹一次） | ✅ |

## 它不做什么（重要）

**这些限制是设计上的取舍，不是待修的 bug。请在依赖它之前确认能接受。**

| 限制 | 说明 |
|---|---|
| **没有恢复功能** | 只能上传，不能下载。本地硬盘坏了，你要自己去 [pan.xunlei.com](https://pan.xunlei.com) 手动找文件。这是单向备份器，不是双向同步盘。 |
| **不保留版本历史** | 文件更新后会再传一份，云盘里出现 `a.txt` 和 `a(1).txt`。默认行为是**只报告、不删除**云端旧版本（`versionsMode=keep`）；代码里存在一个 `replace` 模式可删旧版本，但**当前没有任何 UI 能开启它**，且删除需同时满足 7 个安全条件（模式显式开启、本轮已核实上传成功、id 属于上传前快照、不是本次新文件、同源文件名、本轮无配额/鉴权错误、未超单轮删除上限）。简言之：**正常使用它不会删你云盘上的任何文件**。注意：`replace` 模式确实能删，界面没有入口，但 `host.js` 会照 `config.json` 的值走 —— 如果你手工把这个值改成 `replace`，它就会删（仍要同时满足上面 7 个条件、每轮最多 20 个）。 |
| **云端是单层目录** | 子目录结构不会保留。`照片\2023\a.jpg` 和 `照片\2024\a.jpg` 在云端会变成 `a.jpg` 和 `a(1).jpg`，**无法从名字判断来源**。检测到同名冲突时会在日志里明确告警。 |
| **单文件上限 2 GB** | 超过的直接跳过（可在设置里调大，但越大越慢）。 |
| **跳过点开头的目录** | `.git`、`.ssh`、`.config` 等不会被备份。 |
| **不跟随符号链接/junction** | 会统计并在日志里告警，但不会备份其内容。如需备份，请把目标目录直接加入监视列表。 |
| **拒绝系统目录** | `C:\Windows`、`Program Files`、`ProgramData` 等会被拒收，防止误选导致上传整个系统盘。 |
| **无删除同步** | 本地删了文件，云端保留（对备份来说这是正确行为）。 |

## 已知边界

上面是"设计上不做什么"，这里是**实现层面确实做不到的**，一并写清楚，免得你按想象使用。

1. **只上传，不能下载或恢复**。云端不是唯一副本，本地文件丢了就没了；要取回请自己去 [pan.xunlei.com](https://pan.xunlei.com) 手动下载。
2. **云端版本策略默认 `keep`，默认路径绝不删云端文件**。同名文件不覆盖，云端会同时存在 `a.txt` 和 `a(1).txt`。
3. **目录结构不会在云端还原**。所有文件平铺到一个文件夹里，`照片\2023\a.jpg` 与 `照片\2024\a.jpg` 在云端只靠 `a.jpg` / `a(1).jpg` 区分。
4. **熔断状态重启后会丢失**。连续失败达到上限会暂停自动重试，但这个"暂停"只存在内存里；重启应用后它会看着像正常状态，需要你自己看日志确认。
5. **0 字节文件、超过单文件上限的文件会被跳过**。跳过时不报错、不计"失败"，当前界面也不会显示"跳过了 N 个"——只有日志里有记录。如果你的大视频一直没备份上，先去日志里查。
6. **没有「重启引擎」「取消本轮」「只重试某个文件」这些按钮**，因为引擎侧没有对应命令（`host.js` 只提供 `status/scan/runOnce/start/stop/saveConfig/connect/quit`）。能做的只有「立即同步一次」（重跑一轮）和「停止」（会同时关掉自动备份）。
7. **依赖迅雷网页版自动化**。迅雷改版、加验证码、改 DOM 都可能让上传失败；届时界面/日志会出现"云盘网页结构可能变了"这类提示，只能等程序跟进。
8. **安装包没有代码签名**。SmartScreen 和部分杀软会报警（见上面"安装"一节）。
9. **不要同时运行两个本程序实例，也不要在程序运行时用其它工具连同一个浏览器调试端口。** 本程序通过 CDP 控制一个 Edge 实例，两个客户端同时操作同一个页面会互相关闭对方正在用的标签页，导致上传中断且被记为失败。
10. **不做云端对账。** 它只保证"传过"，不保证"现在还在"：云端文件被你自己删掉、被平台按协议清理、或账号被终止，本工具都不会发现，也不会重传。要确认关键文件还在，请定期自己去 [pan.xunlei.com](https://pan.xunlei.com) 看一眼。

## 它是怎么工作的（以及为什么可能违反迅雷协议）

**这一点必须在用之前知道。**

迅雷云盘没有公开的上传 API。本工具的做法是：

1. 后台启动一个 Microsoft Edge（独立 profile，带 `--remote-debugging-port=9222`；端口被占用时会自动回退到 9223–9233，实际端口记录在数据目录）
2. 用 Chrome DevTools Protocol 连上去
3. 从网页版 `pan.xunlei.com` 发出的真实请求里截取 `x-captcha-token` 和 `authorization`
4. 上传时驱动网页版自己的文件选择框，让浏览器发出上传请求

**为什么不自己算 captcha：** 迅雷的 captcha 签名算法分片动态下发，实测无法离线复刻。

**风险披露：**

- 这可能违反**《迅雷网盘服务协议》第 3.12 条**（非经迅雷授权开发的衍生软件均属非法，迅雷有权不事先通知单方面终止账号）和**第 3.4.3 条**（未经书面同意擅自借助迅雷软件发展衍生产品/服务）。本工具**不**绕过任何加密或技术保护措施、不修改迅雷客户端、不伪造签名，也不碰你日常用的浏览器 —— 风险在于"用自动化方式驱动网页版"本身没有获得授权。
- 最坏后果不是"限速"：账号被终止（俗称封号）后，迅雷有权**永久删除云盘里的全部文件**（协议 2.8 条：没有义务返还数据），且无需给予补偿（协议「重要须知 C」）。
- 迅雷接口变更会导致本工具失效，作者不承诺修复或适配。
- 本工具不发送任何遥测数据，所有网络请求只发往 `api-pan.xunlei.com` 和 `pan.xunlei.com`；也因此**出问题作者不会知道**，需要你自己看日志。

**怎么降低风险（而不是"请自行评估"）：** 最省事的自保办法：注册一个专门的迅雷小号给这个工具用 —— 万一被封，没的是这个小号，不是你攒了几年的那个号。另外，重要文件在本地或别的网盘再留一份。

## 安全提示

应用会在本机启动一个带**调试端口**的 Edge（默认 9222，被占用时回退 9223–9233），该端口**没有认证**——本机上任何程序都能连上去，读取这个浏览器里的迅雷登录态。

**边界要说准**：该端口只绑 `127.0.0.1`（本项目没有改这个默认，也没用 `--remote-debugging-address`），所以**局域网和公网都连不上**；风险范围是"本机 + 同一 Windows 用户（或管理员）的任意进程"，而且**应用运行期间端口一直开放**（浏览器是常驻的，不是用完就关）。

实际使用的端口写在 `%APPDATA%\ThunderPanSync\cdp-port.txt`，引擎读它来连浏览器；
读不到时回退 9222。

这不是"CDP 的固有特性、无法消除"：改用 `--remote-debugging-pipe`（本机已实测跑通，管道模式下**没有任何监听端口**）可以彻底消除它，本轮出于改动成本未采用。为了降低风险：

- 应用使用**独立 profile**（`%APPDATA%\ThunderPanSync\browser-profile`），不碰你日常浏览器的登录态
- 退出应用时会终止自己启动的那个 Edge（只杀带本应用 profile 的进程，不动你自己的浏览器）
- 卸载时同样只按 profile 路径过滤清理，**绝不** `taskkill /IM msedge.exe`

如果本机存在不可信的软件，不建议使用本工具。

## 安装

下载 `ThunderPanSync-Setup-1.0.0.exe`，双击安装。

- **只从本仓库的 Release 页下载。** 别人转发/重打包的安装包与本项目无关，我无法保证里面是什么。
- 装到 `%LOCALAPPDATA%\ThunderPanSync`，**不需要管理员权限**
- 会创建桌面和开始菜单快捷方式
- 卸载走「设置 → 应用」，会问你是否删除配置和登录态（**默认保留**）

**安装包没有代码签名。** 首次运行 Windows 会弹「Windows 已保护你的电脑」，需要点「更多信息 → 仍要运行」。那个提示的意思是：**这个程序没有签名，作者无法证明它没干别的**——sys 只给了你"来源不明"这一个信息，请据此决定要不要在装前自己核对源码。

**想彻底删干净**：卸载后手工删掉 `%APPDATA%\ThunderPanSync`。它有多大：本机实测约 **800 MB**（几乎全在浏览器 profile 里，会随使用持续增长；刚装完时较小）。删掉它 = 下次安装要重新登录迅雷。**云盘上已上传的文件不会被删除。**

## 使用

1. 点「添加文件夹…」选择要备份的目录（先加目录：加完你马上能在列表里看到它，登录之前也能加）
2. 点「需要登录迅雷云盘」，在弹出的浏览器窗口里登录（只需一次）
3. 点「开始自动备份」
4. 关窗口 = 最小化到托盘，备份继续

**状态条（5 态，全部从引擎的真实状态派生；形状+颜色双编码，不靠颜色单一通道）：**

- `备份中` — 引擎在跑且没有熔断
- `出错` — 引擎没在跑（比如后台浏览器起不来），会给出原因
- `已暂停（连续失败 N 轮…）` — 熔断：自动重试停了，但点「立即同步一次」仍然可用
- `未在备份（点「开始自动备份」）` — 有目录但没在跑，**这时候你的文件没有在被备份**
- `尚未配置（请添加文件夹）`

登录状态不是一个按钮也不是一种颜色，它是状态条上的副信息（「已登录」/「未登录」）。

**进度条：** 同步时显示 `第 3/12 个 · a.jpg · 2.5 MB / 45 MB`（本轮已传字节 / 本轮总字节），
空闲时显示「空闲」。

**这里不显示"速度"和"剩余时间"**，这是有意的：迅雷网页版在文件上传过程中不给我们任何
文件内进度，引擎只能拿到"这个文件开始传 / 传完了"两个时刻，所以任何 `B/s` 都只能用
"已传字节 ÷ 已耗时"外推，而这两个数不同源（字节数是本轮其他文件的、耗时是当前文件的），
换文件瞬间会剧烈跳变；ETA 同理（实测同一轮里出现过"剩余 1110 小时"）。宁可少显示，
也不显示编出来的数字。

**失败与退避：** 「失败的文件」列表给出每个文件的原因和失败次数。连续失败会
自动退避（间隔翻倍，最长 30 分钟）；连续 5 轮失败会**熔断**，停止自动重试并在
日志里说明。此时点「立即同步一次」仍然可用——熔断只是停掉自动重试，不是锁死。

## 日志

运行日志按天分文件：`%APPDATA%\ThunderPanSync\sync-YYYY-MM-DD.log`。
界面上「打开日志文件」打开的是当天那个文件。`latest.log` 是一个指针文件，
内容为当前活动日志的完整路径（Windows 不能建软链）。
另有 `engine-stderr.log` 保存引擎原始输出，排障时用；它有大小上限，不会无限增长。

## 从源码构建

需要：

- **.NET Framework 4.8**（Win10/11 自带，提供 `csc.exe`）
- **Node.js 18+** —— 构建时用 `(Get-Command node).Source` **把构建机 PATH 里的 `node.exe`
  复制进安装包**作为运行时。因此不同 Node 版本的构建机产出的安装包不同（本机实测用 v26.12.1）
- **NSIS 3.x（makensis）** —— 只有生成安装包时才需要。脚本按下面顺序找：
  1. `%LOCALAPPDATA%\electron-builder\Cache\nsis-3.0.4.1\nsis-3.0.4.1-1mpw4\makensis.exe`
  2. `PATH` 里的 `makensis`
  3. `%ProgramFiles%\NSIS\makensis.exe`
  4. `%ProgramFiles(x86)%\NSIS\makensis.exe`

  如果都没有，`-SkipInstaller` 仍然可用（只产出 exe 与发布目录）；不加该开关会以
  `makensis not found` 失败。

```powershell
# 一键构建（编译 C# → 组装发布目录 → 生成 NSIS 安装包）
.\build-native.ps1

# 只构建目录，不生成安装包（不需要 NSIS）
.\build-native.ps1 -SkipInstaller

# 构建完直接启动
.\build-native.ps1 -RunAfterBuild
```

产物在 `release\ThunderPanSync-Setup-1.0.0.exe`。

### 关于构建产物的可复现性（实测数据，别拿 sha256 当发布校验）

自己重新构建出的安装包**不会**和官方发布的逐字节相同，这有三个已实测的原因：

1. **C# 编译不可复现**。本机 `csc.exe`（4.8.9232，只支持 C# 5）**不认 `/deterministic`**
   （实测报 `fatal error CS2007`），所以每次编译 PE 头里的 `TimeDateStamp`（偏移 `0x88`）
   和托管模块的 MVID GUID（偏移 `0xB388`）都不同 —— 同一份源码连编两次，
   产物等长但差 18 字节。
2. **安装包会嵌入被打包文件的 mtime**。实测：11 个输入文件内容不变，只把其中一个
   的 mtime 从 `2026-01-01` 改成 `2026-06-15`，安装包大小从 26,980,864 B 变成
   26,980,653 B（差 211 B）；改回 mtime 后 sha256 完全恢复。所以文件系统时间戳
   会改变压缩流。
3. **安装包内嵌了 C# exe**，上面第 1 条的 18 字节差异会被放大成整包不同。

已验证的**确定性**部分：NSIS 本身是确定性的（同一输入连跑两次 sha256 逐字节一致）；
`engine/*.js`、`host.js`、`paths.js` 与 `runtime/node.exe` 在不同机器上构建出来
sha256 完全相同（只要 Node 版本一致）。

想做发布校验，请在 `release\` 旁边生成 `sha256` 清单并**只用于检测下载损坏**，
不要用它证明「产物等于源码」。

`installer.nsi` 与 `EULA.txt` 必须是 **UTF-8 带 BOM**，否则 `makensis` 报 `Bad text encoding`。
多数编辑器保存时会丢掉 BOM，所以 `build-native.ps1` 每次构建前自动补 ——
但如果你手工直接跑 `makensis`，要自己确保 BOM 在。

构建脚本是纯 ASCII 的——Windows PowerShell 5.1 会按系统 ANSI 代码页读取无 BOM 的 `.ps1`，注释里的中文会破坏后续 token 解析（这个坑踩过）。

## 架构

```
ThunderPanSync.exe         109,568 B C# WinForms 界面（原生控件）
  ├─ EngineHost.cs                  stdio JSON-RPC 客户端，管理 Node 子进程
  ├─ BrowserManager.cs              启动/隐藏/清理后台 Edge，选调试端口
  └─ MainForm.cs                    界面 + 托盘 + 开机自启 + 进度 + EULA 版本门
runtime\node.exe            100 MB  内嵌 Node 运行时（MIT，见 THIRD_PARTY_NOTICES）
host.js                            JSON-RPC 服务端（仓库根目录）
paths.js                           数据路径（仓库根目录；一律 %APPDATA%，安装目录只读）
engine\engine.js                   同步引擎（扫描/上传/核查/版本策略）
engine\cdp.js                      自研 CDP 客户端（替代 playwright，用 Node 内置 WebSocket）
```

界面与引擎通过 **stdio JSON-RPC** 通信——不占端口、不触发防火墙、随主进程退出。

**为什么不用 Electron：** 试过。239 MB，界面是 Chromium 渲染的网页。换成原生 WinForms 后主程序 107 KB（实测 109,568 B），界面是真 Windows 控件。

## 数据位置

- 配置/日志/状态：`%APPDATA%\ThunderPanSync\`
  - `config.json` 设置　`state.json` 已上传记录（原子写，断电不会写坏）
  - `sync-YYYY-MM-DD.log` 按天分文件　`latest.log` 指向当天日志
  - `engine-stderr.log` 引擎原始输出　`cdp-port.txt` 实际调试端口
- 浏览器登录态：`%APPDATA%\ThunderPanSync\browser-profile\`
- 安装目录只放程序，不写任何数据

`state.json` 用「写临时文件 → fsync → rename」的原子替换。直接覆盖写时，断电或
强杀会留下 0 字节/半截 JSON，下次启动解析失败就会把已备份的内容全部重传。
文件真的损坏时会先备份成 `state.json.corrupt-<时间戳>` 再从空状态开始。
